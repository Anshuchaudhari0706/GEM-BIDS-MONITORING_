1. SUMMARY OF ROOT CAUSE & PAGINATION FIX
--------------------------------------------------------------------------------
Previous Issue:
  Yesterday's multi-page scan returned only 10 unique records even though GeM
  reported numFound = 5,718,972. Every page was returning duplicate records because
  the "page" parameter was incorrectly nested inside the "param" sub-object in the
  POST request body.

Root Cause Fix:
  1. Payload Structure Correction:
     Moved "page": page parameter to the top-level of the JSON payload object:
       {
         "page": page,
         "param": {
           "search": "",
           "sort": "Bid-Start-Date-Latest"
         }
       }
     This instructed GeM's Solr search backend to correctly advance page-by-page.

  2. Solr Array Unwrapping:
     GeM Solr JSON outputs wrap values inside single-element arrays (e.g.
     b_total_quantity: [350], is_high_value: [False], final_start_date_sort: ["..."]).
     Created unwrap_val() helper to extract integer headcounts, values, and dates.
